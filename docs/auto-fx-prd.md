## 1. 系统概述

### 1.1 产品名称
Auto-FX（自动化外汇交易系统）

### 1.2 产品定位
建行亚洲资产托管业务的外汇交易自动化模块，为托管客户提供与证券服务相关的外汇交易直通式处理（STP）服务。

### 1.3 核心目标
- 实现外汇兑换从手动到直通式处理（STP），目标 STP 率 100%
- 消除汇率风险暴露（从 24-48 小时缩短至分钟级）
- 缩短资金闲置时间（从 3-5 天缩短至 <24 小时）
- 降低人力成本（后台工时从每月 160 小时降至接近 0）
- 确保合规支付，避免二次违规

## 3. 核心业务场景

### 3.1 场景一：公司行动（股息派发）

**触发条件：** 外币股息贷记到客户账户

**目标流程：**
1. T+0 上午：外币股息贷记到客户账户
2. T+0（数秒内）：系统识别符合规则，自动生成外汇指令
3. T+0（分钟级）：自动执行外汇交易，锁定汇率
4. T+0 同日：基准货币资金到账，自动推送确认报告

**规则配置示例：**
- 规则 1：GBP 股息 → 全额兑换为 USD，支付日执行
- 规则 2：EUR/JPY/AUD/CAD 股息 → 全额兑换为 USD
- 规则 3：其他货币，金额 >5 万 USD 等值 → 全额兑换
- 规则 4：其他货币，金额 ≤5 万 USD 等值 → 不自动兑换（累积后批量处理）

### 3.2 场景二：证券交易（证券买入）

**触发条件：** 证券买入交易执行

**目标流程：**
1. T 日：交易执行，成交记录发送至托管系统
2. T 日（分钟内）：Auto-FX 引擎识别交易，计算所需金额（含预估税费）
3. T 日（即时）：自动执行外汇交易，锁定汇率
4. T+2：证券与资金顺利交割

### 3.3 场景三：CSDR 罚款

**触发条件：** 系统接收到 CSD 罚款发票

**目标流程：**
1. 系统通过 API 自动接收结构化罚款发票数据
2. 数据推送至"应付账款"队列
3. Auto-FX 规则引擎触发（到期日前第 2 个工作日执行）
4. 系统自动预留等值资金
5. 自动执行外汇交易（聚合多笔，获取最优汇率）
6. 自动生成并发送支付指令（附发票号）
7. 自动更新支付状态，完成电子对账

### 4.1 规则配置模块

#### 4.1.1 页面：规则列表

**路径：** `/rules`

**页面元素：**
- 顶部筛选栏：客户账号、规则状态（全部/生效中/待审核/已停用）、创建时间范围
- 规则列表表格：
  - 列：规则 ID、客户名称、客户账号、触发币种、目标币种、金额区间、点差、状态、创建人、创建时间、操作
  - 操作按钮：编辑、停用/启用、查看详情
- 右上角：「新建规则」按钮

#### 4.1.2 页面：新建/编辑规则

**路径：** `/rules/create` 或 `/rules/:id/edit`

**表单字段：**

```
基本信息：
├── 客户账号（下拉选择，关联 CIF）
├── 规则名称（文本输入）
├── 生效日期（日期选择器）
└── 失效日期（日期选择器，可选）

触发条件：
├── 触发场景（下拉：股息派发 / 证券买入 / CSDR 罚款）
├── 触发币种（多选：GBP, EUR, JPY, AUD, CAD, CHF 等）
└── 指令模式（单选：常行指令 / 按事件逐一指示）

兑换规则：
├── 目标币种（下拉选择，默认为账户基准货币）
├── 金额区间配置（可添加多个区间）：
│   ├── 最小金额（USD 等值）
│   ├── 最大金额（USD 等值）
│   ├── 兑换方式（全额兑换 / 不兑换 / 保留原币种）
│   └── 点差（基点 bps）
└── 执行时间（下拉：立即 / 支付日 / 到期日前 N 个工作日）

通知设置：
├── 通知邮箱（最多 5 个）
└── 通知场景（多选：交易成功 / 交易失败 / 规则变更）
```

**业务逻辑：**
- 规则创建后状态为「待审核」
- 创建人与审核人不能为同一人
- 规则审核通过后状态变为「生效中」
- 修改已生效规则后状态重新变为「待审核」
- 金额区间不可重叠

### 4.2 自动换汇引擎（后端服务）

#### 4.2.1 触发机制

```
事件触发流程：
  存款入账 / 证券交易 / 罚款发票
    ↓
  事件监听器捕获
    ↓
  匹配 Auto-FX 规则（按客户账号 + 币种 + 金额区间）
    ↓
  命中规则？
    ├── 是 → 生成外汇指令 → 执行交易
    └── 否 → 忽略（保留原币种）
```

#### 4.2.2 核心处理逻辑

```
function processAutoFX(event) {
  1. 识别事件类型（股息/交易/罚款）
  2. 查询客户 Auto-FX 规则（状态=生效中）
  3. 匹配触发条件（币种 + 金额区间）
  4. 查询实时汇率（基准汇率 + 点差）
  5. 生成外汇即期交易指令
  6. 提交至外汇平台执行
  7. 接收交易确认
  8. 更新资金台账
  9. 发送通知（邮件）
  10. 记录审计日志
}
```

#### 4.2.3 汇率计算

```
客户成交价 = 基准汇率 + 点差（bps）

示例：
  基准汇率 EUR/USD = 1.0750
  点差 = 5 bps = 0.0005
  客户买入价 = 1.0755
  兑换金额 = 1,750,000 EUR
  客户支付 = 1,750,000 × 1.0755 = $1,882,125.00
  银行收入 = 1,750,000 × 0.0005 = $875.00
```

> ⚠️ 待确认：点差收入入账科目

## 5. 数据模型

### 5.1 核心实体

```sql
-- Auto-FX 规则表
auto_fx_rules {
  id              UUID PRIMARY KEY
  customer_id     VARCHAR        -- 客户 CIF
  customer_name   VARCHAR        -- 客户名称
  account_no      VARCHAR        -- 结算账号
  base_currency   VARCHAR(3)     -- 基准货币（如 USD）
  rule_name       VARCHAR        -- 规则名称
  trigger_type    ENUM           -- 触发场景：DIVIDEND / TRADE / CSDR
  trigger_currencies VARCHAR[]   -- 触发币种列表
  instruction_mode ENUM          -- STANDING（常行）/ PER_EVENT（按事件）
  target_currency VARCHAR(3)     -- 目标兑换币种
  status          ENUM           -- PENDING_REVIEW / ACTIVE / SUSPENDED
  effective_date  DATE           -- 生效日期
  expiry_date     DATE           -- 失效日期（可选）
  created_by      VARCHAR        -- 创建人
  reviewed_by     VARCHAR        -- 审核人
  created_at      TIMESTAMP
  updated_at      TIMESTAMP
}

-- 金额区间配置表
auto_fx_tiers {
  id              UUID PRIMARY KEY
  rule_id         UUID REFERENCES auto_fx_rules(id)
  min_amount      DECIMAL        -- 最小金额（USD 等值）
  max_amount      DECIMAL        -- 最大金额（USD 等值）
  action          ENUM           -- CONVERT / HOLD（兑换/保留）
  spread_bps      DECIMAL        -- 点差（基点）
  sort_order      INT            -- 排序
}

-- 自动换汇交易记录表
auto_fx_transactions {
  id              UUID PRIMARY KEY
  rule_id         UUID REFERENCES auto_fx_rules(id)
  customer_id     VARCHAR
  account_no      VARCHAR
  trigger_type    ENUM           -- DIVIDEND / TRADE / CSDR
  trigger_ref     VARCHAR        -- 触发事件引用 ID
  source_currency VARCHAR(3)     -- 源币种
  target_currency VARCHAR(3)     -- 目标币种
  source_amount   DECIMAL        -- 源金额
  target_amount   DECIMAL        -- 目标金额
  base_rate       DECIMAL        -- 基准汇率
  spread_bps      DECIMAL        -- 点差
  deal_rate       DECIMAL        -- 成交汇率
  bank_revenue    DECIMAL        -- 银行点差收入
  status          ENUM           -- PENDING / EXECUTING / COMPLETED / FAILED
  failure_reason  VARCHAR        -- 失败原因
  executed_at     TIMESTAMP      -- 执行时间
  settled_at      TIMESTAMP      -- 交割时间
  created_at      TIMESTAMP
}

-- 邮箱通知配置表
auto_fx_notifications {
  id              UUID PRIMARY KEY
  rule_id         UUID REFERENCES auto_fx_rules(id)
  email           VARCHAR
  notify_on       VARCHAR[]      -- ['SUCCESS', 'FAILURE', 'RULE_CHANGE']
}

-- 审计日志表
auto_fx_audit_log {
  id              UUID PRIMARY KEY
  entity_type     VARCHAR        -- RULE / TRANSACTION
  entity_id       UUID
  action          VARCHAR        -- CREATE / UPDATE / REVIEW / EXECUTE
  actor           VARCHAR        -- 操作人
  details         JSONB          -- 操作详情
  created_at      TIMESTAMP
}
```

### 5.2 数据量级

- 持股 500 支，涉及 12 种货币
- CSDR 罚款：多笔小额（案例中 8 笔，总额约 2 万 EUR）

## 7. 异常处理

### 7.1 已定义的异常场景

| 异常场景 | 处理方式 |
|---------|---------|
| 外汇交易执行失败 | 标记为失败，发送通知，人工介入 |
| 账户余额不足 | 交易暂停，发送预警通知 |
| 汇率数据异常 | 暂停自动兑换，使用备用汇率源或转人工 |
| 规则冲突（多条匹配） | 按优先级执行最高优先级规则 |
| 审核超时 | 发送催办通知，规则保持待审核状态 |
| 货币假期 | 自动调整至最近营业日执行 |
| 并发冲突 | 使用资金锁定机制，防止重复兑换 |
| 支付失败（CSDR） | 自动重试，超过次数后转人工 |

## 10. 风险提示

1. **审核与自动化的矛盾**：若每笔交易都人工审核，将严重影响 STP 目标。建议仅审核规则配置和异常交易。
2. **汇率风险转移**：系统识别到执行期间汇率仍可能波动，需明确风险承担方。
3. **规则配置复杂度**：需提供模板和向导，避免配置错误。
4. **系统集成复杂度**：多系统对接，任一环节故障可能导致流程失败，需设计降级方案。
5. **CSDR 场景 API 依赖**：需尽快确认 CSD API 可用性。
6. **合规审计**：外汇交易涉及严格金融监管，需完整审计追踪。
